## 1. 目标与范围

最终提供一个跟随玩家的光源，照亮区域**外径约为逻辑 Canvas 宽度的 2/3**；当前 1200×800 对应外径 800px、外半径 400px。柔和边缘包含在此范围内，照明不是敌人可见性、攻击距离或碰撞规则。

按顺序交付：①基础照明；②玩家和一种敌人的真实素材法线验证；③rim、明暗色阶、脚底软阴影和可靠回退；④覆盖全部玩家动画、普通敌人、Boss 及五种障碍物。

本期采用假体积受光，不重建精灵真实几何。障碍物有法线不等于能够挡光；几何遮挡、长距离投影、额外火盆/枪口光源、HDR/Bloom、视野迷雾及整个渲染器迁移不在本期范围。保持现有简单实现，不引入渲染框架、Worker 或新游戏事件总线。

## 3. 拟采用的模块与合成合同（To-Be）

### 3.1 最小职责划分

下列模块现已落地；另用 spriteLayout.ts 共享帧/几何规则、lightingShader.ts 保存着色器。表格仍说明各自职责，不代表新增模拟系统。

| 拟新增位置 | 职责 |
| --- | --- |
| `src/game/config/lighting.ts` | 光照参数、质量档位、按 AssetId 登记的材质预设；不持有局内状态 |
| `src/game/render/lighting/lightingMath.ts` | 衰减、明暗倍率、坐标与材质尺寸换算；供针对性回归使用 |
| `src/game/render/lighting/normalProfiles.ts` | 一次生成共享法线图集，管理预设及素材包围盒元数据 |
| `src/game/render/lighting/lightingRenderer.ts` | WebGL 初始化、着色输出缓存、纹理上传、能力检测、降级和释放 |

只在 `renderWorld.ts` 接入绘制适配，页面负责资源版本与 renderer 生命周期。沿用已有加载器与图集；不要给 Player、Monster、Obstacle 添加 GPU 对象或一份光照坐标，也不扩展 `UpdateWorldContext`。

拟定窄接口：`prepareFrame(frame)` 准备本帧受光精灵，`drawSprite(ctx, sprite)` 在原位置绘制着色结果或原图，`dispose()` 释放资源。`frame` 只含逻辑视口、本帧实际世界→屏幕变换、玩家光源和必要精灵描述；`sprite` 含资源身份/版本、源帧矩形、目标矩形/变换、材质与原有透明度。renderer 不接收 runtime setter，不读取 DOM 输入，不生成游戏 ID、不消耗业务随机。

### 3.2 混合渲染与原有层级

1. 本帧只计算一次实际镜头变换及光源位置；包含钳制和震屏，不能从屏幕中心或未经钳制的 camera ref 推断位置。
2. 对需要法线的可见精灵生成小型描述列表，批量绘制到有限大小的离屏着色图集；动画选择/几何计算提取为共享小函数，只计算一次，不在预处理和原绘制路径各复制一套分支。
3. Canvas 仍按原世界顺序绘制；受光精灵在原 `drawImage` 位置使用着色图集对应区域，保持坐标、锚点、尺寸、镜像、透明度和实体遮挡顺序。不能把所有角色最后统一叠上去。
4. 世界内容完成后施加一次基础照明倍率，再绘制不受光照影响的屏幕 HUD/暂停面板及必要提示。仅提取这些相关绘制块，不顺带拆分整个 renderWorld。
5. 先记录血条、伤害字、闪现图标、Boss 预警、词缀和受击效果的现有层级；提示移到光照之后的变化须明确记录并截图核对，保持原有相对位置与提示间的顺序。弹体、区域与爆炸默认仅接受基础照明，不增加法线或动态光源。

所有新增画布按视口或有限图集分配，禁止为 6000×6000 世界新建全尺寸颜色/法线缓冲。一次着色多个精灵后再供 Canvas 读取，不做逐角色 WebGL→CPU 像素读回。统一 shader 输出、混合与 Canvas 接收侧的预乘 Alpha 约定，防止透明边缘发黑或变亮。混合画布的实际传输成本是阶段 2 的验收点，不能预先宣称免费。

### 3.3 避免距离衰减重复计算

采用单一颜色倍率合同，全部分量在 0～1 的显示范围内，不追求 HDR。设 `A` 为环境 RGB，`D(d)` 为光色×强度×距离衰减，`f` 为法线响应（无体积时为 1），则：

```text
f(N,L) = mix(1, max(dot(N,L), 0), normalStrength) // N、L 均归一化，强度限制在 0～1
B(d) = clamp(A + D(d), brightnessFloor, 1)       // 基础照明，世界最终统一乘一次
T(d,N) = clamp(A + D(d) * f(N,L), brightnessFloor, 1)
K(d,N) = T(d,N) / max(B(d), epsilon)             // 精灵着色只输出修正倍率
最终角色颜色 = 原色 * K * B = 原色 * T
```

按 RGB 分量计算；环境与光色、衰减、下限及量化规则由两条路径共享。法线关闭时 `K=1`；距离超出外半径时 `D=0`、`K=1`，环境光不被法线再压暗。禁止“shader 已算完整 T，再把全局 B 乘一次”。阶段 2 必须用数值回归及截图验证此合同；Canvas 渐变与 shader 的采样近似误差应记录并消除可见接缝。

## 4. 配置与所有对象复用法线的方案（To-Be）

### 4.1 初始参数与单位

以下是起始调试值和验收定义，不是当前配置；视觉调优允许修改数值，但须保留字段含义与记录。

| 字段 | 类型 / 初始值 | 语义与兼容行为 |
| --- | --- | --- |
| `enabled` | boolean / true | 关闭时恢复原画面；GPU 故障只切基础照明，不等同于关闭 |
| `diameterRatio` | number / 2/3 | 外径/逻辑 Canvas 宽；`outerRadius = width * diameterRatio / 2` |
| `softEdgeRatio` | number / 0.25 | 软边宽/外半径；当前内半径 300px、外半径 400px |
| `attenuationExponent` | number / 2 | 内半径以内为 1；软边 `a=(1-t)^exponent`，外半径及以外为 0 |
| `ambientIntensity`、`ambientColor` | number / 0.30；RGB / [0.75,0.80,1] | 环境倍率；RGB 是归一化显示值，两条合成路径一致 |
| `lightIntensity`、`lightColor` | number / 0.85；RGB / [1,0.90,0.75] | 单玩家光源；中心来自 player 的世界坐标，初始偏移为 0 |
| `lightHeight` | number / 120 | 与逻辑像素同尺度的假高度，用于计算入射方向，不是角色碰撞高度 |
| `brightnessFloor` | number / 0.10 | 各通道最低倍率，避免除零；战斗可读性仍须人工验收 |
| `normalStrength` | number / 0.35 | 0 表示无体积修正；从温和强度调起，避免叠加原画高光后失真 |
| `rimStrength`、`lightLevels` | number / 0.35；integer / 0 | 标准档 rim 关闭；高档按材质启用。0 表示连续明暗，4 表示四档光照 |
| `quality` | enum / standard | basic、standard、high，含义见第 7 章；初始不新增持久化设置 |

配置加载时拒绝 NaN/Infinity，约束颜色、比例、强度和数量；缺失可选字段回退本表默认值，未知材质使用所属类别默认预设并在开发模式提示。亮度色阶只量化光照，不新增整屏最终颜色量化管线；各项默认值在实现后写入配置并同步 design.md。

### 4.2 一张通用法线能否适配所有尺寸

**尺寸可以通用，外形不宜全部强行使用同一球面。** 用精灵包围盒的归一化 UV 映射同一模板，大小改变不增加法线资源；现有障碍物包含工作台、火盆、骨骸和石块，只用球面会让平面也像气球。

推荐初始化一次生成**一张包含三个 64×64 预设的法线图集**：球面、圆柱/胶囊、倒角块面；地面使用常量平面法线。RGBA8、不计边框与 mipmap 时合计约 48KiB，实例数、动画帧数和显示尺寸不改变此容量。必要的图集边框仍计入实际预算。法线采样后重新归一化；原色保持现有像素采样，法线可用线性采样平滑过渡，跨预设须防串色。

法线图集按渲染器/GL context 共享，不按角色、障碍实例或帧复制。仍有每帧纹理采样、光照和合成成本；共享法线的显存不等于整个光照系统的显存。先以共享纹理为主；只有测量表明解析式法线更快时，才替换生成方式，不同时维护两套生产方案。

| 对象 / 已确认素材 | 首选预设 | 适配与例外 |
| --- | --- | --- |
| 玩家待机、行走、闪现；普通敌人 1～4（含 enemy_4 两张图集） | 胶囊 | 同一角色动画组使用稳定体积范围，复用模板并调整曲率/强度 |
| Boss 的 boss / boss2 动画 | 球面或扁球面 | 用形状参数控制宽高与凸度，两组动画分别核对；不逐帧制作法线 |
| obstacle_1：骨骸，512×256 | 扁球面 | Alpha 提供外轮廓；不能据此恢复眼窝等内部几何 |
| obstacle_2：工作台，512×256 | 倒角块面 | 保留台面平坦感，用低强度避免整张图变成圆柱 |
| obstacle_3：火盆，512×256 | 扁球面 | 火焰与盆体在同张图中；不自动添加火盆光源。必要的火焰自发光遮罩须作为单独视觉调优项记录 |
| Obstacle_4：石堆，512×256 | 倒角块面 | 只近似整体体积，不为每块石头生成纹理 |
| obstacle_5：立石，256×256 | 倒角块面 | 用较高纵向体积与较低 rim，核对尖端高光 |

预设选择是待截图验证的建议，全部素材必须进入覆盖表；允许调参数或换共享预设，不以增加实例专用贴图作为默认补救。

### 4.3 包围盒、缩放与 rim

- 材质元数据按 `AssetId` 登记 `normalProfile`、体积范围、锚点/脚点、曲率、强度和 rim 开关；障碍物由 `Obstacle.image` 对照 manifest 找到身份。元数据属于表现配置，不改碰撞框或 MonsterType。
- 在资源加载/版本变化时扫描一次 Alpha 求体积范围；动画组在统一锚点坐标下取稳定范围，避免每帧包围盒变化造成高光跳动。闪现的变宽源帧须按真实帧矩形换算。明显的原图投影/透明留白可用素材级范围覆盖，禁止逐帧 CPU 扫描。
- 不因求体积范围改变原图裁剪、目标矩形或锚点；求范围的 Alpha 阈值与最终透明绘制分开，不能照搬 demo 的 0.5 丢弃阈值而切掉半透明边缘。
- 显示尺寸变化只更新变换/参数；非等比缩放校正法线 XY 斜率并归一化，镜像和旋转同步转换法线方向，不能只翻转颜色 UV。所有计算在同一屏幕坐标约定下进行。
- rim 只作为轮廓局部修正，不是完整厚度图或精确几何法线。高档以 Alpha 四邻域梯度叠加；采样钳制在当前帧半 texel 安全范围，兼顾图集边框，禁止读入相邻帧。
- 默认不为静态障碍另生成逐素材法线。若高档 rim 经测量成为热点，可按唯一静态素材缓存边缘信息一次；记录新增纹理预算。动画不预烘焙全部帧，低档关闭 rim 时必须实际跳过四次邻域采样。

## 6. 资源与性能标准

### 6.1 实现要求

- 共用一个 WebGL context；程序、buffer、法线图集、阴影纹理初始化一次，context 恢复时重建一次。通过纹理缓存按唯一素材+版本上传原色，不能按实体/帧重复上传或每帧创建纹理、shader、Canvas。
- `MAX_TEXTURE_SIZE` 等能力在初始化时查询并缓存。boss2 不直接假定可整张上传：超限按现有帧矩形重排为设备支持的页，处理最后一帧的真实宽度；分页只发生在 GPU 缓存侧，不移动原始资源。
- 批量准备受光精灵，允许在互不重叠的输出图集槽位内按材质/纹理分组；Canvas 最终仍按原顺序取槽位绘制。着色不能以逐对象切换/读取画布的方式无上限增长。
- 视口外对象不进入法线通道；世界→屏幕包围盒检测只影响绘制，不从 World 删除实体或跳过模拟。无直射光且 K=1 时可直接用原图；这是数学等价路径，不是漏覆盖。
- 静态障碍的资源/法线可以缓存，最终受光颜色随玩家、镜头变化，不能只烘焙一次后永久复用。输出缓存当帧有效，不能无限按实体×帧×光照位置累计。
- 默认法线预设约 48KiB；着色输出及合成缓冲初始预算不超过 16MiB，新增光照 GPU 资源总估算预算不超过 64MiB，计入重复上传的原色、分页、边框、法线、FBO/输出及必要中间画布的 GPU 存储。CPU 解码图像/Canvas 内存另记，不能把 GPU 估算当浏览器总内存。
- 达到容量或纹理限制时有界回退，保持所有对象继续基础照明；记录降级原因。标准验收场景不能靠持续降级到 basic 宣称完整法线性能达标。

纹理尺寸因设备而异；批量绘制、资源复用和避免同步 CPU 像素读回有明确收益方向，但混合画布传输仍须测量。[WebGL 性能与限制建议](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)

### 6.2 测量方法与预算

以下为实施前确定的验收预算；实测结果另见验收记录，预算未放宽。阶段 0 在指定桌面目标设备上记录 CPU/GPU、浏览器版本、刷新率、逻辑 1200×800 和 CSS 缩放；不直接用 demo 的 FPS 作项目基线。若需调整预算，先说明设备证据和质量影响并记录决定，不在验收时无说明放宽。

| 场景 | 固定负载 / 比较方式 |
| --- | --- |
| 普通场景 | 玩家、30 普通敌人、100 弹体、24 障碍；光源中心/边缘均测试 |
| 压力场景 | 玩家、100 普通敌人、500 弹体、24 障碍及 1 Boss，含受击与爆炸表现；使用可重复渲染夹具，不改变正式刷怪规则 |
| 生命周期 | 相同素材反复新局 20 次，切换基础/标准/高档，触发资源重载；context 丢失/恢复至少 3 次 |

同一夹具用固定位置/种子与模拟时间，依次测关闭、basic、standard、high；每档预热 10 秒、采样 60 秒、重复 3 次。分别记录可见对象数量、RAF 帧间隔、CPU 渲染提交时间、长帧、上传次数、draw calls、缓存大小和估算内存。不能把 `performance.now()` 包住 WebGL 提交的耗时当 GPU 完成时间；有可用计时扩展时异步取 GPU 数据，否则用浏览器性能面板并标明限制。

标准档目标：相对关闭光照的同负载基线，新增 CPU 渲染耗时中位数 ≤2ms、P95 ≤4ms；基线稳定 ≥58 FPS 时，开启后平均 ≥55 FPS，P95 帧间隔增幅 ≤20%。60 FPS 的整体目标仍是每帧约 16.7ms；基线不达标时单列既有成本，同时报告新增开销，不能只报一个平均 FPS。

预热后相同素材的正常换帧新增上传次数应为 0；重复新局后纹理/FBO/context 数量稳定，旧资源版本释放，无单调增长的受持有缓存。高档超预算先关闭 rim/额外阴影、降低光照缓冲分辨率，再评估进一步方案；无法满足标准档时停留在阶段 2 调整，必要的渲染架构替换另行报告范围。

## 7. 质量档、故障回退与验证

| 档位 / 状态 | 行为合同 |
| --- | --- |
| enabled=false | 原渲染结果，不保留暗幕；用作基线与功能关闭 |
| basic | Canvas 基础照明，无 GPU 法线/rim/额外脚底阴影；故障回退目标 |
| standard | 全部目标对象共享法线、可选光照色阶，rim 关闭；脚底阴影仅对需要的材质开启 |
| high | standard + 按材质启用 Alpha rim；先达标再提供，不以高档为启动前提 |
| WebGL 创建/编译/上传失败或 context lost | 当前/下一可用帧转 basic，原图片继续绘制；不阻塞加载页、不改阶段或重启游戏 |
| context restored / 素材版本变化 | 用已有加载结果重建所需缓存；成功前保持 basic，不反复在每帧重试初始化 |
| 卸载 | 清理 context 监听、GPU/Canvas 缓存和引用；不增加残留 RAF/定时器 |

资源超限可以单素材回退并诊断；该素材的完整覆盖验收仍未通过。输出质量降低时用滞回/稳定策略避免频繁切档，不把性能问题隐藏为永久跳过 Boss/障碍。恢复失败可保持 basic 并提供开发诊断，不影响战斗逻辑。

依赖环境具备时按 [AGENTS.md](../AGENTS.md) 执行已有命令；不得编造新的现成门禁：

```powershell
pnpm test:game
pnpm exec tsc --noEmit --incremental false
pnpm lint:build
pnpm check:assets
```

涉及生产行为时单独运行 `pnpm exec next build --webpack`，不与类型检查并行。不要用带安装/端口清理副作用的包装作只读检查，不用导出 Excel 验证光照。最初规划时无 node_modules；实施已按锁文件安装现有依赖并执行检查，详见验收记录。
