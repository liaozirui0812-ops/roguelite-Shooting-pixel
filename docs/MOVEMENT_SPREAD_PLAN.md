# 移动散布与动态十字准星方案

状态：核心方案已实现，2026-10-20 完成自动回归和浏览器功能验收；完整战斗平衡与四边/震屏手感仍待人工试玩。下文保留规则与配置合同，实际实现位置及验证记录见第 7、9 节。

## 1. 预期体验与范围

玩家移动越接近当前最大速度，射出的子弹越容易向瞄准方向的两侧偏移；停下后散布逐步恢复。鼠标位置显示由上、下、左、右四条线段组成的十字准星，散布越大，四条线段距中心越远。精准度越高，同样移动状态下的弹道与准星越集中。

本方案采用以下起始规则，参数需实机试调：

- 保留现有按键移动与松键即停。通过散布的扩张、恢复时间表现“逐步稳定”，不增加角色惯性或改动碰撞手感。
- 依据碰撞结算后的实际位移计算速度比例。顶住墙没有位移时按静止处理，沿墙滑动按实际移动比例处理。
- 保留武器原有弹道结构，散弹枪仍然一发五颗、按扇形排列；移动增加每颗弹体的随机角度偏移。
- 精准度影响固有扇形、原有随机散射和新增移动散射；不影响伤害、暴击、弹速、弹体大小、弹数或射程。
- 只替换战斗画布内的鼠标指示。屏幕外敌人的方向箭头保持原用途。

若“慢慢停止”要求角色本体持续滑行，需要另行设计加减速、碰撞与闪现衔接；本提案不把该移动改造作为散布的前置条件。

## 2. 当前实现（源码核对）

| 内容 | 当前行为与入口 | 接入影响 |
| --- | --- | --- |
| 更新顺序 | `systems/updateWorld.ts` 先执行 `movementSystem`，再执行 `weaponSystem` | 移动系统收尾更新散布，射击可在同一步读取 |
| 移动 | `movementSystem.ts` 直接按当前速度增减位置，再处理边界与障碍；没有普通移动速度向量或加减速过程 | 不能用不存在的 velocity 字段，也不能用 `isMoving` 代替真实位移 |
| 速度单位 | `runtime/FixedStepClock.ts` 固定 60Hz；现有速度是 px/模拟步 | 速度分子分母保持同单位，不能混入 RAF 的帧间隔 |
| 有效移速 | `rules/combatStats.ts::deriveCombatStats().moveSpeed` 包含玩家速度、狂暴、武器倍率、受击减速；移动系统中有同等计算 | 散布计算复用相同口径，不重新拼另一套速度公式 |
| 斜向移动 | 同时增加 X、Y 位移，没有归一化，斜向自由移动速度为轴向的 √2 倍 | 必须在速度比例中明确处理，不能顺便改变角色移动规则 |
| 固有散布 | `config/weapons.ts::spreadAngle` 是弧度；`weaponSystem.ts` 用它安排多弹体扇形，并叠加 `U(-0.5,0.5) × spreadAngle × 0.3` | `spreadAngle` 保留含义，不再新增一份相同扇形配置 |
| 武器差异 | 手枪/狙击/RPG 的 `spreadAngle=0`；散弹为 0.3、五颗；冲锋枪为 0.05、单颗 | 冲锋枪虽然只有一颗，也已有随机散射 |
| 精准度 | `WeaponConfig`、`Player`、派生属性与武器随机词条均未定义精准度 | 精准度是本次拟新增的独立属性，不能借用暴击字段 |
| 鼠标 | `useGameInput.ts` 保存 client 坐标；`page.tsx` 画布已有 `cursor-crosshair` CSS | 当前未发现自绘动态鼠标准星；浏览器显示的指针样式可能受环境影响 |
| 瞄准 | 首发、RPG 延迟第二发、枪体与身体朝向仍有相对画布中心求角度的代码 | 镜头滞后/边界时存在 R11 偏差，接入精准准星需一起覆盖相关瞄准入口 |
| 延迟弹 | RPG 两联装第二发通过 `runtime.schedule(..., 700)` 生成，另有一套角度/弹体逻辑 | 不能只修改首发循环 |

上述路径默认相对于 `src/game/`；页面和 hook 位于 `src/app/page.tsx`、`src/hooks/useGameInput.ts`。架构依据见 [DESIGN.md](../DESIGN.md) 第 2、3.2、3.3、3.10、5.4 章；相关债务见 [technical_debt.md](../technical_debt.md) 的 R02、R11。行号随当前其他开发变化，实施时按函数重新定位。

## 3. 配置表设计（To-Be）

运行配置仍使用 TypeScript 模块。建议新增 `src/game/config/aim.ts`，集中存放下列三组配置；不把 `public/assets/buff_config.xlsx` 当作在线调参入口。表内角度使用度，进入计算时统一转弧度。

### 3.1 全局散布配置 `AIM_CONFIG`

| 字段 | 类型 | 单位 / 范围 | 建议默认值 | 含义 |
| --- | --- | --- | --- | --- |
| `enabled` | boolean | — | true | 统一启用移动散布、精准度缩放和动态准星；false 时沿用原散布与原生指针 |
| `movementCurveExponent` | number | > 0 | 1.5 | 目标移动散布系数为速度比例的该次方；低速更稳定 |
| `expandMs` | number | ms，≥ 0 | 100 | 移动散布系数从 0 增至 1 的时间；0 表示立即跟随 |
| `recoverMs` | number | ms，≥ 0 | 220 | 系数从 1 恢复至 0 的时间；0 表示立即恢复 |
| `accuracyBasePoints` | number | 精准点，> 0 | 100 | 精准度缩放公式的基准值 |
| `accuracyMinPoints` | number | 精准点 | 0 | 本期不设计负精准度惩罚 |
| `accuracyMaxPoints` | number | 精准点，≥ min | 300 | 有效精准度上限；默认最小散布倍率为 0.25 |

`expandMs/recoverMs` 表示走完整个 0～1 区间的时间；恢复一半区间只需一半时间。该时间只控制散布，不控制人物位置。精准度只改角度，不改变这两个时间。

### 3.2 武器移动散布配置 `WEAPON_AIM_CONFIG`

类型建议为 `Record<WeaponType, { movementHalfAngleDeg: number }>`。字段为**全速时新增随机散射半角**，必须 ≥ 0，每种武器必须有记录，不能依靠缺项时静默回退。

| 武器 ID | 现有 `spreadAngle`（rad，保留） | 弹数 | 新增 `movementHalfAngleDeg` | 静止最大偏角，精准 0 | 全速稳定后最大偏角，精准 0 |
| --- | --- | --- | --- | --- | --- |
| `pistol` | 0 | 1 | 4° | 0° | ±4° |
| `shotgun` | 0.3 | 5 | 6° | ±11.17° | ±17.17° |
| `smg` | 0.05 | 1 | 7° | ±0.43° | ±7.43° |
| `sniper` | 0 | 1 | 9° | 0° | ±9° |
| `rpg` | 0 | 1 | 5° | 0° | ±5° |

散弹枪静止的 ±11.17° = 固有扇形半角约 8.59° + 原随机散射半角约 2.58°。冲锋枪单颗不应用固定扇形，只保留约 ±0.43° 的原随机散射。表中最大偏角是整个弹束的角度包络，不是每颗子弹都会到达边界，也不是命中率。

这组参数用于首次试玩：狙击鼓励停步，冲锋枪的移动惩罚较明显，手枪便于移动点射。它们没有经过当前关卡、成长或 Boss 战平衡验证。

### 3.3 准星表现配置 `CROSSHAIR_CONFIG`

| 字段 | 类型 | 单位 / 范围 | 建议默认值 | 含义 |
| --- | --- | --- | --- | --- |
| `minGapPx` | number | Canvas 逻辑 px，≥ 0 | 3 | 中心至线段内端的最小距离 |
| `maxGapPx` | number | Canvas 逻辑 px，≥ min | 64 | 可读性上限，防止准星过度占屏 |
| `referenceDistancePx` | number | 世界/逻辑 px，> 0 | 180 | 把角度换成显示距离的固定参考距离 |
| `armLengthPx` | number | Canvas 逻辑 px，> 0 | 7 | 四条线段固定长度 |
| `lineWidthPx` | number | Canvas 逻辑 px，> 0 | 2 | 线段宽度 |
| `outlineWidthPx` | number | Canvas 逻辑 px，≥ 0 | 1 | 线段周围黑色描边的厚度 |
| `color` | string | Canvas 颜色 | `#FFFFFF` | 准星主体颜色 |
| `outlineColor` | string | Canvas 颜色 | `#000000` | 背景复杂时仍可辨认 |
| `dashAlpha` | number | 0～1 | 0.4 | 闪现禁射期间的准星透明度 |

配置约束在开发检查/测试中显式报错。计算出的最大包络半角须小于 89°，防止 tan 换算失效；不引入运行时吞错或重复备用配置。

### 3.4 新增精准度属性

建议新增 `Player.accuracyPoints: number`，默认 0，单位为“精准点”，是局内全局属性。所有武器共用，换枪保留，新局重置，普通跨关保留。不要同时保存一个 accuracyBonus 和一个重复累计的当前精准值。

派生值：`A = clamp(player.accuracyPoints, accuracyMinPoints, accuracyMaxPoints)`。

散布倍率：`K = accuracyBasePoints / (accuracyBasePoints + A)`。

| 有效精准度 A | 散布倍率 K | 说明 |
| --- | --- | --- |
| 0 | 1.00 | 保持基础散布 |
| 25 | 0.80 | 总角度缩小 20% |
| 50 | 0.667 | 总角度约缩小 33.3% |
| 100 | 0.50 | 总角度缩小 50% |
| 300 | 0.25 | 默认上限，总角度缩小 75% |

“精准 +25”指增加 25 点，不表示命中率 +25%，也不表示直接减去 25°。首期只接入属性、公式与测试入口；全员初始为 0，不自动向商店、升级或武器词条池投放精准奖励。若需要可获取成长，应作为明确的后续内容接入类型、效果、候选池、文案与上限，避免只加配置却无入口。

## 4. 计算流程与弹道合同

### 4.1 当前速度比例

在 `movementSystem` 中记录位置更新前的 `p0`，完成边界与障碍处理后得到 `p1`：

```text
actualStepDistance = hypot(p1.x - p0.x, p1.y - p0.y)
axisMaxStepDistance = deriveCombatStats(player, now).moveSpeed
inputLength = hypot(inputX, inputY)       // 相反方向先抵消，每轴只取 -1/0/1
directionMaxStepDistance = axisMaxStepDistance × max(1, inputLength)
r = directionMaxStepDistance > 0
    ? clamp(actualStepDistance / directionMaxStepDistance, 0, 1)
    : 0
targetBloom = r ^ movementCurveExponent
```

这里的“当前最大速度”是当前状态下、沿输入方向自由移动的最大速度：包括装备/成长、武器移速倍率、狂暴和受击减速。受击后若仍达到减速后的当前最大速度，仍为 100%；减速不会额外奖励精准。若今后设计慢走/模拟摇杆，其较小移动量必须相对于未降低的自由移动上限计算，不能把输入力度同时乘进分母。

使用方向长度只为兼容现有斜向移动：自由轴向和自由斜向均为 100%，不把“斜着跑更快”变成散布差异，也不在本需求中修复斜向移速。不可简单拿实际位移除以轴向速度后钳制，那会使沿墙斜向滑动等中间速度丢失比例。

碰撞前的 `isMoving` 可能为 true，但碰撞后没有位移，因此本规则不得读取该标记判断散布。零速度、相反按键、边界和滑墙均需单独测试。

### 4.2 平滑移动散布

建议只新增一份权威运行状态 `GameWorld.aimSpread: { movementBloom: number }`，系数范围 0～1，初始化为 0。普通移动每个固定模拟步更新一次：

```text
duration = targetBloom > movementBloom ? expandMs : recoverMs
movementBloom = duration == 0
    ? targetBloom
    : moveTowards(movementBloom, targetBloom, fixedStepMs / duration)
```

`moveTowards` 限制单步变化量且不越过目标。例如 r=0.5 时目标系数为 0.3536；全速稳定后松键，110ms 后系数约为 0.5、220ms 后为 0。固定步长有最多一个模拟步的取整差异。

使用现有 `runtime.stepMs`，不复制一个新的计时器，也无需新增 TickContext 参数。不得使用 RAF delta、Date.now、setTimeout 或在 render 中推进恢复。

### 4.3 最终散布与采样

以下所有角度进入计算前转为弧度；`W` 是已有 `weaponConfig.spreadAngle`，`N` 是 `bulletsPerShot`，`M` 是新增的移动半角：

```text
patternOffset(i) = N > 1 ? -W/2 + W × i/(N-1) : 0
legacyJitterHalf = W × 0.15
jitterHalf = (legacyJitterHalf + M × movementBloom) × K
finalAngle(i) = aimAngle + patternOffset(i) × K + U(-1,1) × jitterHalf
envelopeHalf = ((N > 1 ? W/2 : 0) + legacyJitterHalf + M × movementBloom) × K
```

`U(-1,1)` 用 `runtime.random() * 2 - 1`。每颗弹体独立采样，保持现有散弹随机方式；半角为 0 时不额外调用随机数。该均匀采样关于瞄准轴对称，左右偏移指相对于射击方向的角度偏差，不是修改世界 X 坐标。

关键约束：

- 枪口位置、枪体和基础瞄准方向仍沿 `aimAngle`；只有初始弹道方向取 `finalAngle`。不要把散布当成枪体视觉后坐力重复叠加。
- 首发与第二发弹体的 vx/vy 均使用 `finalAngle`。当前 Bullet 没有 angle 字段，RPG 加速通过归一化已有 vx/vy 保持方向，无需新增重复角度状态；回归需确认加速后仍沿偏移方向。
- 已出膛弹体不因玩家停步、换枪或提高精准度重新改方向。
- 精准 0、移动系数 0 时，公式与已有静止散布一致；关闭功能时直接保留旧路径及其随机调用顺序。
- 开启移动散布会增加原本无散射武器的随机采样，后续战斗随机序列可能变化；不能要求旧战斗种子逐弹完全复现，也不为此新增另一套战斗随机源。

### 4.4 数值例子：手枪

以下为进入稳定状态后的结果，使用默认配置、精准 0。即时加速/停步仍受扩张与恢复时间影响。

| 速度比例 r | 移动系数 r^1.5 | 弹道最大偏角 | 准星内间距 gap |
| --- | --- | --- | --- |
| 0% | 0 | 0° | 3.00 px |
| 25% | 0.125 | ±0.50° | 4.57 px |
| 50% | 0.354 | ±1.41° | 7.44 px |
| 75% | 0.650 | ±2.60° | 11.17 px |
| 100% | 1 | ±4.00° | 15.59 px |

全速、精准 100 时，手枪变为 ±2°、gap 约 9.29px。静止手枪已经没有角度误差，精准度不会进一步把准星缩到负间距。现有键盘自由移动主要只有 0/100% 两种速度比例；中间值来自碰撞部分位移及后续可能的慢走输入，过渡期则由 movementBloom 提供。

## 5. 四段准星与瞄准坐标

### 5.1 准星绘制

中心位于鼠标对应的 Canvas 逻辑坐标，固定保持水平/竖直四臂，不跟随枪朝向旋转，不绘制中心点、圆圈或额外箭头。

```text
gap = clamp(minGapPx + referenceDistancePx × tan(envelopeHalf), minGapPx, maxGapPx)

上：(cx, cy-gap-armLength) → (cx, cy-gap)
下：(cx, cy+gap) → (cx, cy+gap+armLength)
左：(cx-gap-armLength, cy) → (cx-gap, cy)
右：(cx+gap, cy) → (cx+gap+armLength, cy)
```

先以 `lineWidthPx + 2 × outlineWidthPx` 绘黑线，再用 `lineWidthPx` 绘白线，使用平直线帽。线长与线宽保持不变，变化的只有中心间距。

准星读取与射击相同的 `envelopeHalf`，不额外用百分比归一化，也不单独延迟平滑，否则精准度提高后可能仍显示相同大小。散弹静止准星比手枪大是正确反馈。默认参考距离下，散弹静止 gap 约 38.55px、全速约 58.63px。

这是固定 180px 参考距离的角度指示，并非鼠标处的实际落点边框；投射物飞行、敌人移动、碰撞体积和距离仍影响命中。保持 gap 不随鼠标远近变化，可避免鼠标移动本身导致准星忽大忽小。触及 maxGapPx 后显示饱和，不能再据准星尺寸区分更大的角度，但弹道仍由真实角度计算。

在世界镜头变换恢复、光照合成之后绘制，放在暂停遮罩之前。准星不受世界光照变暗，不使用 React 的低频快照刷新，更不在绘制时采样弹道随机数。

### 5.2 R11：坐标接入前置项

仅绘制新准星不能解决已有瞄准偏差。实施时需共享一个小型视口换算合同，建议 `src/game/rules/aim.ts` 中提供纯坐标函数，视口快照仍作为表现 ref 保留：

1. client → Canvas 逻辑坐标：分别乘 `logicalWidth / rect.width`、`logicalHeight / rect.height`，处理页面偏移与 CSS 缩放。
2. Canvas → 世界坐标：使用当前已显示帧的实际相机平移，包含平滑、边界钳制和震屏；基础矩阵若含缩放则使用相应逆变换。
3. `aimAngle = atan2(pointerWorld.y - player.y, pointerWorld.x - player.x)`。
4. 首发、RPG 第二发、枪体角度、身体朝向/光影翻转共用该合同，避免只修一处。
5. 同时覆盖 Canvas 暂停/继续按钮命中换算，避免显示位置和点击位置在缩放时分离。

建议将“已呈现视口”写入现有镜头相关表现 ref，模拟只读其快照，不让 render 写入玩家、弹体或散布状态。第一次绘制前由新局/视口初始化入口建立合法快照；新局清除上一局视口引用，并在首个合法快照建立前阻止射击，不能默认回退到错误的画布中心公式。

这里选择以已呈现画面为瞄准依据：震屏期间鼠标下的世界点会相应变化，射击按该显示点求角度；不另外调用表现随机数或推进相机。固定刷新率对比时使用相同指针/视口输入，移动散布自身应与刷新率无关。镜头/震屏下的最终手感需要实机验收。

R11 核心坐标换算已随本次实现接入；完整实机视觉验收仍未完成，见 technical_debt 的对应状态。

### 5.3 指针显示与交互

动态准星仅在 `playing && !isPaused`、指针在画布内、视口快照有效且无设置/加载遮挡时显示；此时画布使用 `cursor: none`。其余情况恢复合适的原生指针。

使用页面/hook 的表现 ref 保存 pointer 是否位于画布及其有效性；不创建第二份 React Player/散布状态。首次进入、pointer enter 时更新位置，pointer leave、blur、visibilitychange、pointercancel 清除有效性并清理按住射击，防止遗留准星或离屏自动射击。恢复焦点后收到新的指针进入/移动再显示。

现有鼠标监听和挂载清理由 `useGameInput` 与 runtime hook 协调，新增监听必须对称移除。现有暂停时不更新 `world.mousePos` 的行为可以保留，暂停界面使用原生指针；恢复时必须等有效位置更新，不能在旧鼠标坐标处闪出准星。

## 6. 状态生命周期与特殊弹体

| 场景 | `movementBloom` | 精准度 | 射击 / 准星行为 |
| --- | --- | --- | --- |
| 初始/新局 | `createWorld()` 初始化 0；`resetRunWorld()` 重建 | `createPlayer()` 初始化 0 | 同时初始化/失效旧局的视口与指针 ref |
| 普通移动 | 移动系统收尾更新一次 | 读取当前值 | 本步首发读取更新后的系数 |
| 松键/顶墙 | 目标系数为 0，按 recoverMs 恢复 | 保持 | 弹道和准星一起恢复 |
| 换弹 | 继续随移动更新 | 保持 | 准星继续显示当前精度，不因换弹自动变准 |
| 换枪 | 保留系数，使用新枪的移动半角/固有扇形 | 保留 | 换枪禁射时限保持原规则；准星立即反映新枪 |
| 闪现 | 触发时设为 1，闪现期间保持 1；结束后按普通速度恢复 | 保持 | 闪现仍不能射击，准星以 dashAlpha 显示；不把瞬移位移代入速度比 |
| 暂停 | 冻结，恢复后继续 | 保持 | 隐藏自绘准星、恢复原生指针；不能利用暂停等待散布恢复 |
| 失焦/切到后台 | 沿用 useGameRuntime 的自动暂停，冻结当时系数 | 保持 | 准星隐藏、释放射击；手动恢复且重新收到有效指针后显示 |
| 离开 playing | 阶段入口置 0 | 常规跨关保留，新局重置 | 隐藏准星，沿用现有模拟任务取消；下一关不继承移动散布 |
| 开关配置关闭 | 运行状态初始化/重置为 0，不推进散布 | 字段保留但不参与角度 | 沿用旧弹道与原生指针；R11 坐标修复不因该开关撤回 |

闪现结束的那个模拟步，若本步曾发生闪现位移，仍按闪现处理；下一普通移动步再计算速度比例。由进入 movementSystem 时的闪现状态与本步是否消费成功的请求共同判断，不能只看结束时已经变为 false 的 active。

RPG 两联装第二发必须在回调中重新检查阶段、暂停、玩家存活、当前武器/节点、弹药、换弹/换枪、闪现和有效视口。回调读取当前鼠标、当前位置、当前精准度与最新已结算的 movementBloom，重新采样方向，不沿用首发的散布或准星尺寸。保持既有 700ms、弹药、伤害、爆炸与加速规则。

`GameRuntime.step()` 在本步 movementSystem 之前执行到期任务，因此延迟第二发读取的是最近一个已完成模拟步的散布；可有一个固定步的时间差。保留该调度合同，不为散布重排全局更新顺序或移动全部延迟任务。

## 8. 验证与验收

### 8.1 实现时的自动回归

- 速度比例：自由轴向/斜向均为 1；无输入、相反键、完全顶墙为 0；斜向滑墙和部分边界位移保留比例；零最大速度不除零。
- 动态过程：0→1 扩张约 100ms，1→0 恢复约 220ms；中途改变速度目标不超调；0ms 配置即时完成；30/60/144Hz 相同固定步输入结果一致。
- 实际发射链：同一随机样本下，静止/全速/停步恢复中的首发符合边界；五种武器都覆盖，验证散弹五颗及旧扇形、冲锋枪旧随机角度，精准 0/100/300 及超过上限。
- 偏移对称：为角度采样注入 random=0、0.5、接近1，分别落在负边界、中心、正边界；中心样本无偏移，半角为0不额外调用随机。实际射击测试还需区分暴击等其他随机调用，无需用一次小样本命中率代替公式边界验收。
- RPG 组合：第一/第二发之间移动、停步、改变瞄准、切枪、换弹、闪现、暂停、死亡、离开阶段；vx/vy 对应采样角度，加速后仍沿偏移方向。到期任务按既有模拟步边界读取。
- 生命周期：换枪不清空 bloom，跨关清空，新局清空 bloom/精准/旧视口；暂停冻结；失焦释放输入；禁用配置恢复旧散布。
- 坐标/绘制：中心、镜头滞后、四边与四角、不同 DOM rect、震屏与身体翻转；准星与射击读取相同 envelope；绘制前后战斗状态、随机调用次数、冷却均不改变。
- 配置约束：缺武器记录、非法角度/时间/间距、无效精准区间应显式失败；更新手工夹具后检查公共类型兼容。

依赖已具备时执行 `pnpm test:game`、`pnpm exec tsc --noEmit --incremental false`、`pnpm lint:build`。本方案只用 Canvas 线段、不新增图片；若实施扩大到资源装配，再运行 `pnpm check:assets` 并检查实际绘制。需要生产行为证据时单独运行 `pnpm exec next build --webpack`，不得与类型检查并行。

### 8.2 人工验收链

1. 从正常菜单选手枪进入战斗，将鼠标停在空旷方向：静止准星紧凑；按住移动后约 100ms 达到最大，松键后约 220ms 收回；持续射击观察弹道同步收拢。
2. 改变移动方向、斜着移动、顶墙和沿墙滑行：自由移动最大尺寸一致，完全顶墙后恢复；没有位置抖动或额外滑行。
3. 测试入口分别设精准 0、100：相同移动下角度与 gap 均减小；静止散弹仍有五颗扇形，不能变成单颗或丢失伤害。
4. 覆盖五种武器，移动中换枪/换弹，再验 RPG 两联装的第二发；准星不因换枪意外重置为静止。
5. 走向四条地图边界并快速移动，改变画布显示尺寸：未加散布的瞄准中心与枪体方向对齐鼠标；震屏期间按已呈现画面判断。
6. 移动中闪现、暂停/恢复、移出画布、切换窗口、打开设置：无重复指针、无残留十字、无离屏射击，暂停不能等待恢复精度。
7. 清场进入升级和商店再进入下一关、死亡后重开：菜单使用原生指针；跨关 bloom 清空，精准跨关保留而新局重置。
